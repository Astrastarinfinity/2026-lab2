# Справочно-методический материал к лабораторной работе

## 1. Защищенный удаленный доступ (SSHv2)

### 1.1. Синтаксис настройки
Для работы подсистемы SSHv2 маршрутизатор требует обязательного наличия настроенного доменного имени и сгенерированной пары асимметричных ключей RSA (рекомендуемый размер модуля — не менее 1024 бит).

```text
Router(config)# ip domain-name <ДОМЕННОЕ_ИМЯ>
Router(config)# crypto key generate rsa [modulus <512-4096>]
Router(config)# ip ssh version 2
Router(config)# line vty <НАЧАЛЬНЫЙ_НОМЕР> <КОНЕЧНЫЙ_НОМЕР>
Router(config-line)# login local
Router(config-line)# transport input ssh
```

* `transport input ssh` — принудительно ограничивает входящие протоколы, запрещая незащищенные сессии Telnet.
* `crypto key generate rsa modulus 2048` — генерирует пару ключей с длиной модуля 2048 бит.

## 2. Динамическая конфигурация узлов (DHCP и DHCP Relay)

### 2.1. Конфигурация локального DHCP-сервера
Пул адресов формируется в глобальном режиме конфигурации. Диапазоны статических адресов (шлюзы, серверы) исключаются **до** инициализации пула.

```text
! Исключение одного адреса или диапазона
Router(config)# ip dhcp excluded-address <НАЧАЛЬНЫЙ_IP> [<КОНЕЧНЫЙ_IP>]

! Создание пула и параметров аренды
Router(config)# ip dhcp pool <ИМЯ_ПУЛА>
Router(dhcp-config)# network <АДРЕС_СЕТИ> <МАСКА_ПОДСЕТИ>
Router(dhcp-config)# default-router <IP_ШЛЮЗА>
Router(dhcp-config)# dns-server <IP_DNS_1> [<IP_DNS_2>]
```

### 2.2. Получение адреса интерфейсом маршрутизатора
```text
Router(config-if)# ip address dhcp
```
Интерфейс отправляет запросы `DHCP Discover`. При успешной аренде маршрутизатор не только назначает адрес и маску, но и автоматически инсталлирует полученный от сервера маршрут по умолчанию (`S*`) с административной дистанцией `AD = 254`.

### 2.3. Агент ретрансляции DHCP (DHCP Relay Agent)
По умолчанию маршрутизаторы не пересылают широковещательные кадры (`255.255.255.255`). Если DHCP-сервер отделен от клиентов маршрутизатором, на интерфейсе, **принимающем** клиентские широковещательные запросы, настраивается пересылка в Unicast:

```text
Router(config-if)# ip helper-address <IP_СЕРВЕРА_НАЗНАЧЕНИЯ>
```
*Интерфейс перехватывает широковещательный UDP-запрос клиента (порт 67/68), вставляет свой IP-адрес в заголовок запроса (`GIADDR`) и пересылает его указанному серверу в виде одноадресного пакета.*

## 3. Трансляция сетевых адресов (NAT / PAT)

Механизм **Port Address Translation (PAT / NAT Overload)** осуществляет мультиплексирование множества частных IP-адресов (RFC 1918) в один или несколько публичных IP-адресов за счет модификации номеров портов транспортного уровня (L4).

### 3.1. Определение ролей интерфейсов
Перед созданием правил трансляции каждый физический/логический интерфейс помечается направлением:
```text
Router(config-if)# ip nat inside   ! Подключение к локальной (частной) сети
Router(config-if)# ip nat outside  ! Подключение к внешней (публичной) сети
```

### 3.2. Трансляция с перегрузкой в адрес интерфейса
Используется, когда внешнему интерфейсу выделен одиночный динамический или статический публичный IP-адрес.

```text
Router(config)# ip access-list standard <ИМЯ_ACL>
Router(config-std-nacl)# permit <СЕТЬ_ИСТОЧНИКА> <WILDCARD_МАСКА>
Router(config)# ip nat inside source list <ИМЯ_ACL> interface <ВНЕШНИЙ_ИНТЕРФЕЙС> overload
```

### 3.3. Трансляция с перегрузкой с использованием пула адресов
Применяется, когда в распоряжении организации имеется блок публичных адресов.

```text
Router(config)# ip access-list standard <ИМЯ_ACL>
Router(config-std-nacl)# permit <СЕТЬ_ИСТОЧНИКА> <WILDCARD_МАСКА>

Router(config)# ip nat pool <ИМЯ_ПУЛА> <START_IP> <END_IP> netmask <МАСКА_СЕТИ>
Router(config)# ip nat inside source list <ИМЯ_ACL> pool <ИМЯ_ПУЛА> overload
```

> **Примечание:** Ключевое слово `overload` активирует сохранение состояния сессий по номерам TCP/UDP-портов (PAT). Без этого параметра адреса из пула будут выделяться по схеме статического динамического NAT (1:1), пока пул не исчерпается.

## 4. Списки контроля доступа (ACL)

### 4.1. Базовые правила обработки списков доступа
1. **Последовательность (Top-Down):** строки списка анализируются сверху вниз до первого совпадения.
2. **Неявный запрет (Implicit Deny):** в конце каждого списка всегда присутствует невидимое правило `deny any` (для Standard) или `deny ip any any` (для Extended).
3. **Расчет обратной маски (Wildcard Mask):** 
   $$\text{Wildcard Mask} = 255.255.255.255 - \text{Subnet Mask}$$
   *Пример: для подсети `/29` (`255.255.255.248`):*
   $$255.255.255.255 - 255.255.255.248 = 0.0.0.7$$

---

### 4.2. Стандартные списки доступа (Standard ACL)
Фильтруют пакеты **исключительно по IP-адресу источника**.

#### Шаблон синтаксиса:
```text
Router(config)# ip access-list standard <ИМЯ_ИЛИ_НОМЕР>
Router(config-std-nacl)# [permit | deny] <IP_ИСТОЧНИКА> <WILDCARD_МАСКА>
Router(config-std-nacl)# [permit | deny] host <IP_ИСТОЧНИКА>
Router(config-std-nacl)# [permit | deny] any
```

#### Применение для фильтрации сессий управления (VTY):
Для ограничения доступа по SSH/Telnet список привязывается к терминальным линиям с помощью команды `access-class`:
```text
Router(config)# line vty <НАЧАЛО> <КОНЕЦ>
Router(config-line)# access-class <ИМЯ_ACL> in
```

---

### 4.3. Расширенные списки доступа (Extended ACL)
Позволяют фильтровать трафик по протоколам L3 (IP, ICMP) и анализировать порты источника и назначения L4 (TCP, UDP).

#### Обобщенный шаблон команды:
```text
Router(config)# ip access-list extended <ИМЯ_ИЛИ_НОМЕР>

Router(config-ext-nacl)# [permit | deny] <ПРОТОКОЛ> \
    <ИСТОЧНИК> <WILDCARD_ИСТОЧНИКА> [ОПЕРАТОР ПОРТ_ИСТОЧНИКА] \
    <НАЗНАЧЕНИЕ> <WILDCARD_НАЗНАЧЕНИЯ> [ОПЕРАТОР ПОРТ_НАЗНАЧЕНИЯ]
```

#### Основные операторы портов:
* `eq <номер|имя>` — строгое равенство (equal).
* `neq <номер|имя>` — все, кроме указанного (not equal).
* `gt <номер>` — строго больше (greater than).
* `lt <номер>` — строго меньше (less than).
* `range <старт> <конец>` — диапазон портов.

---

### 4.4. Разбор структуры правил Extended ACL на абстрактных примерах

* **Пример 1: Разрешение всего IP-трафика между конкретными подсетями**
  ```text
  Router(config-ext-nacl)# permit ip 10.10.0.0 0.0.255.255 172.16.5.0 0.0.0.255
  ```
  *Любой протокол стека IP от источника `10.10.0.0/16` к подсети назначения `172.16.5.0/24` разрешен.*

* **Пример 2: Клиентский запрос к сервису (фильтрация по порту назначения)**
  Клиент обращается к серверу `198.51.100.50` по протоколу HTTPS. Клиентский порт является динамическим (`>1023`), а порт назначения сервиса строго фиксирован (`443`):
  ```text
  Router(config-ext-nacl)# permit tcp any host 198.51.100.50 eq 443
  ```

* **Пример 3: Ответ сервера внешнему клиенту (фильтрация по порту источника)**
  Если сервер `198.51.100.50` отправляет ответ клиенту, пакет исходит с локального сервисного порта сервера (`80/http` или `53/domain`):
  ```text
  Router(config-ext-nacl)# permit tcp host 198.51.100.50 eq 80 any
  Router(config-ext-nacl)# permit udp host 198.51.100.50 eq domain any
  ```

* **Пример 4: Фильтрация служебного трафика ICMP**
  Протокол ICMP не использует номера портов L4:
  ```text
  Router(config-ext-nacl)# permit icmp 10.0.0.0 0.255.255.255 host 198.51.100.50
  ```

---

### 4.5. Применение ACL на физические интерфейсы

```text
Router(config-if)# ip access-group <ИМЯ_ACL> <in | out>
```

| Направление | Момент проверки пакета | Типичное применение |
|---|---|---|
| **`in`** (входящий) | До обработки таблицей маршрутизации (Pre-routing). | Быстрая блокировка нежелательного трафика на периметре. |
| **`out`** (исходящий) | После принятия решения о маршрутизации и определения выходного порта (Post-routing). | Контроль трафика, покидающего данный сегмент / направляющегося к подключенным серверам. |

| Просмотр списка настроенных внешних NTP-серверов | `show ntp associations` |
